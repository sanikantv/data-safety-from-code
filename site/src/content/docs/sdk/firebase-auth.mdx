If your Android app includes **Firebase Authentication** from Google, its data counts as data your app collects. According to the vendor, it collects user IDs (collected, not shared: the vendor acts as a service provider).

Matched dependencies: `com.google.firebase:firebase-auth`.

<Aside type="tip" title="Source">From Google's own Play data disclosure: [firebase.google.com](https://firebase.google.com/docs/android/play-data-disclosure). Checked 2026-10-26.</Aside>

## What to declare

| Data type | Collected | Shared | Ephemeral | Purposes |
|---|---|---|---|---|
| User IDs <br/><small>Generated Firebase Authentication user ID</small> | Yes | No | No | App functionality; Account management |

Whether each type is **required or optional** for users depends on your app: optional only if users can turn it off and the app honors that.

## Only declare these if they apply

| Data type | When | Collected | Shared | Purposes |
|---|---|---|---|---|
| Email address | Only with email/password, email link, or a federated provider that returns an email | Yes | No | App functionality; Account management |
| Phone number | Only with phone auth, phone as a sign-in method, or SMS second factor | Yes | No | App functionality; Account management |
| Name | Only if you set a display name or a federated provider returns one | Yes | No | App functionality; Account management |

The skill lists these under *Needs your review* and checks the code for the condition (for example a `setUserId` call) before you include them.

## Notes

Always collects the device IP address (security and abuse prevention during sign-up and sign-in) and a generated Firebase Auth user ID. Other data depends on the sign-in methods you enable. Federated providers may also return profile/contact info depending on the scopes you request.

## The CSV rows this sets

These are the rows of Google's [Data safety CSV](/reference/csv-format/) that Firebase Authentication turns to `true` (or `false` for the ephemeral question). Columns: question ID, response ID, value. You also answer the required/optional row for each type.

```csv
PSL_DATA_TYPES_PERSONAL,PSL_USER_ACCOUNT,true
PSL_DATA_USAGE_RESPONSES:PSL_USER_ACCOUNT:PSL_DATA_USAGE_COLLECTION_AND_SHARING,PSL_DATA_USAGE_ONLY_COLLECTED,true
PSL_DATA_USAGE_RESPONSES:PSL_USER_ACCOUNT:PSL_DATA_USAGE_EPHEMERAL,,false
PSL_DATA_USAGE_RESPONSES:PSL_USER_ACCOUNT:DATA_USAGE_COLLECTION_PURPOSE,PSL_APP_FUNCTIONALITY,true
PSL_DATA_USAGE_RESPONSES:PSL_USER_ACCOUNT:DATA_USAGE_COLLECTION_PURPOSE,PSL_ACCOUNT_MANAGEMENT,true
```

## Detect it automatically

`data-safety-from-code` finds Firebase Authentication in your `build.gradle` or version catalog, adds these answers with a link to the source, and merges them with every other SDK and with what your own code sends. You get a CSV to import and a report showing where each answer comes from.
