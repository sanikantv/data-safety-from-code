If your Android app includes **Facebook Android SDK (core, app events, login, share)** from Meta, its data counts as data your app collects. Based on what the SDK does, it collects and shares app interactions, device or other IDs, crash logs.

Matched dependencies: `com.facebook.android:facebook-*`.

<Aside type="caution" title="No official vendor disclosure">This entry is inferred from the SDK's behavior and Google's definitions, not from a vendor data-safety page (see [source](https://developers.facebook.com/docs/app-events/automatic-event-collection-detail), checked 2026-10-26). Check it against your own use of the SDK.</Aside>

## What to declare

| Data type | Collected | Shared | Ephemeral | Purposes |
|---|---|---|---|---|
| App interactions <br/><small>Automatic app events (install, launch) unless AutoLogAppEventsEnabled=false</small> | Yes | Yes | No | Analytics; Advertising or marketing |
| Device or other IDs <br/><small>Advertising ID (AD_ID permission added since SDK 13.0.0)</small> | Yes | Yes | No | Analytics; Advertising or marketing |
| Crash logs <br/><small>Facebook SDK crash reports (SDK crashes only, for Meta's internal use)</small> | Yes | Yes | No | Analytics |

Whether each type is **required or optional** for users depends on your app: optional only if users can turn it off and the app honors that.

## Only declare these if they apply

| Data type | When | Collected | Shared | Purposes |
|---|---|---|---|---|
| Purchase history | Only if the app sells in-app products and automatic purchase logging is on (the default) | Yes | Yes | Analytics; Advertising or marketing |
| Name | Only with Facebook Login, if the app sends the profile off-device | Yes | No | App functionality; Account management |
| Email address | Only with Facebook Login and the email permission, if sent off-device | Yes | No | App functionality; Account management |
| User IDs | Only with Facebook Login, if the app sends the user ID or token off-device | Yes | No | App functionality; Account management |

The skill lists these under *Needs your review* and checks the code for the condition (for example a `setUserId` call) before you include them.

## Notes

Meta publishes no Play Data safety guidance (the Play SDK Index lists it as "Not provided"); this is inferred from Meta's automatic event logging docs. App events (install, launch, Google Play purchases) and app metadata are logged automatically unless AutoLogAppEventsEnabled is false; since v13 the SDK adds the AD_ID permission. Meta uses this data for its own ads products, so it is treated as shared.

## Detect it automatically

`data-safety-from-code` finds Facebook SDK in your `build.gradle` or version catalog, adds these answers with a link to the source, and merges them with every other SDK and with what your own code sends. You get a CSV to import and a report showing where each answer comes from.
