If your Android app includes **OpenAI client libraries** from OpenAI / community, its data counts as data your app collects. What it collects depends on how you use it, so each data type below has a condition.

Matched dependencies: `com.aallam.openai:openai-client`, `com.openai:openai-java`.

<Aside type="caution" title="No official vendor disclosure">This entry is inferred from the SDK's behavior and Google's definitions, not from a vendor data-safety page (see [source](https://support.google.com/googleplay/android-developer/answer/10787469), checked 2026-10-26). Check it against your own use of the SDK.</Aside>

## What it can collect

| Data type | When | Collected | Shared | Purposes |
|---|---|---|---|---|
| Other user-generated content | If the app sends user-written prompts or text | Yes | No | App functionality |
| Photos | If the app sends user images (vision input) | Yes | No | App functionality |
| Voice or sound recordings | If the app sends voice recordings (transcription, realtime audio) | Yes | No | App functionality |
| Files and docs | If the app uploads user files | Yes | No | App functionality |

The skill lists these under *Needs your review* and checks the code for the condition (for example a `setUserId` call) before you include them.

## Notes

No vendor Play disclosure exists. The libraries send whatever the app puts in requests to the OpenAI API. Commonly treated as a service provider (not shared); decide based on your agreement with OpenAI. Calling the API straight from the app also ships your API key.

## Detect it automatically

`data-safety-from-code` finds OpenAI client libraries in your `build.gradle` or version catalog, adds these answers with a link to the source, and merges them with every other SDK and with what your own code sends. You get a CSV to import and a report showing where each answer comes from.
